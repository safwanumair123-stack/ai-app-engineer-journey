# Day 36 — Plan the Enquiry Tracker Interface

## What I learned

- How to define a user before designing an interface.
- How to identify the main jobs a user needs to complete.
- How to plan screens and navigation.
- How to define inputs, validation, and feedback.
- How to turn a command-line workflow into a simple product plan.

## What I planned

I planned a simple Enquiry Tracker for small and micro-businesses.

The product will help a business owner capture customer enquiries, assign priorities, track progress, and follow up without losing important information.

## Main screens

- Dashboard
- Enquiry list
- Create enquiry
- Enquiry details
- Search and filters
- Summary report

## Core user jobs

- Create a new enquiry.
- See a list of enquiries.
- Search for an enquiry.
- Open an enquiry.
- Update an enquiry status.
- Change an enquiry priority.
- Add a next action.
- View a summary report.

## First version scope

The first version will include a dashboard, enquiry list, enquiry creation, enquiry details, status updates, priority updates, search and filters, and a summary report.

It will not include automatic customer emails, automatic WhatsApp messages, automatic quotations, complex user accounts, multi-user permissions, or payment processing.

## Why this matters

Planning the interface before coding helps ensure the application solves a real user problem. It also makes development easier because each screen, input, validation rule, and user action is defined before implementation.
